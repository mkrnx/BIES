## Build this

1. **Schema + service** — `featureFlags` JSON column on SiteSettings; a `server/src/services/featureFlags.service.ts` exposing `getFlags()` (cached, lazy-default: every known slug true), `isEnabled(slug)`, `setFlags(partial)` (validates slugs against a canonical `FEATURE_SLUGS` list exported from one shared module, invalidates cache). Unknown slugs in storage are ignored; missing slugs default true (so new features ship enabled and old DB rows never break).
2. **API** — `GET /api/flags` (public, cached, tiny payload — mount as its own route file; do NOT overload `/api/news/settings`) and `PUT /api/admin/flags` (authenticate + requireRole('ADMIN') + Zod {slug: boolean} partial + audit log + cache invalidation). Add client methods in `src/services/api.js` (`flagsApi.get()`, `adminApi.updateFlags()`).
3. **Server gate middleware** — `featureGate(slug)` in `server/src/middleware/` returning 404 `{error:'Feature disabled'}` when off; mount per-prefix in `index.ts` for: directory→`directories`, points→`points`, events→`events`, media→`media`, news→`news` (EXCEPT keep `GET /news/settings` reachable if other features depend on it — check consumers; safer: gate only the news-content endpoints inside the router), messages→`messages`, wallet→`zaps`, feedback→`feedback`, investors+investments→`investors`, projects→`projects`, cowork's prefix→`cowork` (find it — it landed with PR #328). Admin routes are never gated (admins must be able to re-enable). The flags endpoints themselves are never gated.
4. **Background-service gating** — points scorer: check `isEnabled('points')` at boot AND inside the live `onevent` handler + maintenance tick (cheap cached read) so turning points off stops scoring within the cache TTL without a restart; same treatment for the Twitter/news refresh loop and badge publishing. Log once on skip.
5. **Frontend flags context** — `src/context/FeatureFlagsContext.jsx`: fetch `flagsApi.get()` at app boot (works logged-out too — the GET is public), default-all-true while loading and on fetch error (fail-open so a flaky API never hides the app), refetch on window focus, expose `useFeatureFlags()` / `useFeature(slug)`. Provide from `App.jsx` above the router.
6. **UI gating** — `FeatureRoute` wrapper (renders the existing NotFound/redirect pattern when off) applied to the feature routes in `App.jsx`; `flag:` keys on Navbar `navLinks`, the mobile-drawer array, and `MobileBottomNav` tabs (integrated with #328's customization mechanism); hide inline entry points: Discover's directory entry cards (`directories`), ZapButtons (`zaps`), leaderboard/profile points UI (`points` — PublicProfile stats additions, Profile points card, GamificationToast listener), messages icon (`messages`). Grep each feature's entry points rather than assuming this list is complete.
7. **Admin Features page** — `src/pages/admin/AdminFeatures.jsx` (fork AdminNewsSettings conventions): one row per feature with name/description/toggle, Save (or instant-save per toggle with optimistic UI + revert on error), a note that changes propagate within ~5 minutes to other users (cache TTL) and immediately to the toggling admin. Add the Features tab (lucide `ToggleLeft` or `SlidersHorizontal`) to AdminDashboard tabs + admin route.
8. **i18n** — `features` namespace (per-slug name/description + admin page strings) in EN + ES.
9. **Docs** — short `docs/feature-toggles.md`: slugs, semantics (fail-open, default-enabled, cache TTL, background-service behavior), how to add a new flag.
